## Experimental Package

This package contains unreleased code related to navigation as used in
the CWRU mobile robots.

## Nodes

```clearsilver
node.0 {
 name = map_as_sensor
 desc = `map_as_sensor` converts a map to a point cloud to be used with costmap_2d
 sub{
  0.name= input_map
  0.type= nav_msgs/OccupancyGrid
  0.desc= The input occupancy grid to be turned into a point cloud. The metadata is used to determine the coordinates of the output XY points. Only points with a value of 100 (fatal obstacle cost) will be in the output `PointCloud`. You will likely want to manually mark up a map generated by [[gmapping]] or being input to the [[map_server]] to reflect forbidden zones that are not detected by a laser rangefinder.
  }
 pub{
  0.name= map_cloud
  0.type= sensor_msgs/PointCloud
  0.desc= The output point cloud. You will need to add this topic to the `observation_sources` of your [[costmap_2d]] in order for the obstacles to be respected.
  }
 param {
  0.name = ~channel_name
  0.default = intensity
  0.type = string
  0.desc = The name to set for the channel that accompanies the XYZ points in the output <<MsgLink(sensor_msgs/PointCloud)>>
  1.name = ~intensity
  1.default = 100
  1.type = double
  1.desc = The value of the entry in the output `PointCloud's` channel corresponding to each obstacle point.
  2.name = ~sensor_rate
  2.default = 1
  2.type = int
  2.desc = The rate in Hz that the node should publish an updated `PointCloud`. This could become CPU-intensive at very high rates and dense maps as each time `map_cloud` is generated it must be transformed into the target frame.
  3.name = ~height
  3.default = 1.9
  3.type = double
  3.desc = The height in meters to set for each point in the output `PointCloud`
  4.name = ~target_frame
  4.default = base_link
  4.type = string
  4.desc = The reference frame that `map_cloud` should be transformed into before being output. This should correspond to the `robot_base_frame` parameter of the [[costmap_2d]] you intend on receiving the `map_cloud`. This ensures that the origin of the `map_cloud` is always on the costmap; if it is not, raytracing will fail and the costmap will be unable to use the `map_cloud`.
  }
 req_tf {
  0.to= (value of robot_base_frame parameter)
  0.from= (value of input_map.header.frame_id)
  0.desc= Usually provided by a node responsible for odometry or localization such as [[amcl]].
  }
```
