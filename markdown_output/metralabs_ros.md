## Documentation

This package contains a driver that integrates !MetraLabs Scitos G5
robots into ROS using !MetraLabs\' former \'\'MLRobotic\'\' libraries.

If your Scitos is newer and \'\'only\'\' runs \"MIRA\" try
[scitos_drivers](https://github.com/cburbridge/scitos_drivers) or
[cognidrive_ros](https://github.com/benadler/cognidrive_ros)

### Features

-   [URDF](URDF) model included
-   [diagnostics](diagnostics) support (atm. just the battery state)
-   access Scitos hardware features via
    [dynamic_reconfigure](dynamic_reconfigure) (EBC ports, sonar,
    display led, free run mode\...)
-   publish sonar data as
    [Range message](http://ros.org/doc/api/sensor_msgs/html/msg/Range.html)
    with automatic sonar (de)activation when nodes (un)subscribe (to
    disable sonar remove the \<sonar\> tag from the scitos-config-xml)
-   bumper status / reset supported via topics
-   \...

-   A manipulator supported by !MetraLabs can be controlled via this
    node.
-   Supported protocols: !AmtecMotionProtocol and !SchunkMotionProtocol
-   Each specific manipulator hardware can adjust its specifics via
    subclassing
-   joint naming freedom
-   mimicking joints support
-   [FollowJointTrajectoryAction](control_msgs) server
-   \...

Feel free to ask for improvements or file issues.

## Node API

```clearsilver
node.0 {
  name = ScitosServer node
  desc = The driver for the Scitos robot platform.
  sub {
    0.name = /cmd_vel
    0.type = geometry_msgs/Twist
    0.desc = drive the robot

    1.name = /bumper_reset
    1.type = std_msgs/Empty
    1.desc = reset the bumper
  }
  pub {
    0.name = /odom
    0.type = nav_msgs/Odometry
    0.desc = odometry from Scitos platform
    1.name = /bumper
    1.type = metralabs_msgs::ScitosG5Bumper
    1.desc = bumper status
    2.name = /sonar
    2.type = sensor_msgs/Range
    2.desc = sonar data
    3.name = /diagnostics
    3.type = diagnostics_msgs/DiagnosticArray
    3.desc = diagnostics, see features list
  }
  param {
   group.0 {
    0.name = ~scitos_config_file
    0.type = string
    0.desc = SCITOS config file to use
    0.default = /opt/MetraLabs/MLRobotic/etc/config/SCITOS-G5_without_Head_config.xml
    1.name = ~robot_arm_class
    1.type = string
    1.desc = Which `RobotArm` class to load if not `None` (just an ID, no real classloader yet)

node.1 {
  name = ScitosServer:manipulator
  desc = The manipulator part actually cannot be made a separate node. But it can be disabled if not needed and therefore this list is split.
  sub {
    0.name = /joint_states
    0.type = sensor_msgs/JointState
    0.desc = current joint states
    1.name = schunk/status
    1.type = metralabs_msgs/SchunkStatus
    1.desc = current joint status data
    2.name = schunk/emergency
    2.type = std_msgs/Empty
    2.desc = emergency halt the manipulator
    3.name = schunk/stop
    3.type = std_msgs/Empty
    3.desc = soft stop the manipulator
    
    4.name = schunk/ack
    4.type = std_msgs/Int8
    4.desc = ack/reset the joint with given index
    5.name = schunk/ack_all
    5.type = std_msgs/Empty
    5.desc = ack/reset the manipulator
    
    6.name = schunk/ref
    6.type = std_msgs/Int8
    6.desc = ref the joint with given index
    7.name = schunk/ref_all
    7.type = std_msgs/Empty
    7.desc = ref the manipulator
    
    6.name = schunk/set_velocity
    6.type = metralabs_msgs/IDAndFloat
    6.desc = set velocity for one joint
    7.name = schunk/set_acceleration
    7.type = metralabs_msgs/IDAndFloat
    7.desc = set acceleration for one joint
    8.name = schunk/set_current
    8.type = metralabs_msgs/IDAndFloat
    8.desc = set current for one joint
    9.name = schunk/set_current_max_all
    9.type = std_msgs/Empty
    9.desc = sets maximum current of all joints to their maximum, if supported
    
    10.name = schunk/move_position
    10.type = metralabs_msgs/IDAndFloat
    10.desc = move one joint to position
    11.name = schunk/move_velocity
    11.type = metralabs_msgs/IDAndFloat
    11.desc = move one joint with velocity
    12.name = schunk/move_all_position
    12.type = metralabs_msgs/IDAndFloat
    12.desc = move manipulator to position
    13.name = schunk/move_all_velocity
    13.type = metralabs_msgs/IDAndFloat
    13.desc = move manipulator with velocity
    
    14.name = schunk/trajectory_command
    14.type = trajectory_msgs/JointTrajectory
    14.desc = move manipulator according to trajectory (''Deprecated, use action instead'')
    
    15.name = schunk/<follow_joint_trajectory_action_name>
    15.type = control_msgs/FollowJointTrajectoryAction
    15.desc = move manipulator according to trajectory action; the name can be parameterized
  }
  pub {
    0.name = schunk/trajectory_state
    0.type = control_msgs/JointTrajectoryControllerState
    0.desc = the state information published by the old trajectory executor
  }
  param {
    0.name = robot_description
    0.type = string
    0.desc = The [[URDF]] describing the manipulator (or the full robot)
    0.default = -
    0.name = follow_joint_trajectory_action_name
    0.type = string
    0.desc = The name to for this node's !FollowJointTrajectoryAction server (will be prefixed with namespace ''schunk'')
    0.default = follow_joint_trajectory
  }
}
```
